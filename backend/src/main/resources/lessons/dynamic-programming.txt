WHAT IT IS
Dynamic programming (DP) solves a big problem by splitting it into smaller overlapping problems and saving each answer, so every small problem is solved only once. If plain recursion repeats the same work again and again, DP removes that waste.

REAL-LIFE ANALOGY
Climbing stairs and writing down "ways to reach step 5" on a sticky note. When you later need that number you read the note instead of counting all over again. The sticky notes are the DP table.

KEY TERMS
- State: what dp[i] (or dp[i][j]) means in plain words
- Recurrence: the rule that builds one state from smaller states
- Base case: the smallest states you know directly
- Memoization: top-down, recursion plus a cache
- Tabulation: bottom-up, fill the table in order with loops
- Overlapping subproblems: the same small problem is needed many times

WHEN TO USE IT
- "Count the number of ways" to do something
- "Minimum or maximum" cost, length or profit
- "Is it possible?" with choices at every step
- Plain recursion would try every combination and is far too slow
- Classic shapes: stairs, coins, knapsack, subsequences, grids, strings

CODE: CLIMBING STAIRS (BOTTOM-UP)
int[] dp = new int[n + 1];
dp[0] = 1;
dp[1] = 1;
for (int i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
}
return dp[n];

CODE: COIN CHANGE (MINIMUM COINS)
int[] dp = new int[amount + 1];
Arrays.fill(dp, amount + 1);
dp[0] = 0;
for (int a = 1; a <= amount; a++) {
    for (int coin : coins) {
        if (coin <= a) {
            dp[a] = Math.min(dp[a], dp[a - coin] + 1);
        }
    }
}
return dp[amount] > amount ? -1 : dp[amount];

HOW TO SOLVE ANY DP PROBLEM
1. Define the state in words: "dp[i] is the best answer for the first i items"
2. Write the recurrence: how does dp[i] come from smaller states?
3. Set the base cases (dp[0], dp[1])
4. Decide the order to fill the table (small to large)
5. Read the answer from the right cell (usually the last one)

WORKED EXAMPLE
Climbing stairs: you can climb 1 or 2 steps at a time. Ways to reach step i = ways(i-1) + ways(i-2).
  dp[0]=1  dp[1]=1
  dp[2]=dp[1]+dp[0]=2
  dp[3]=dp[2]+dp[1]=3
  dp[4]=dp[3]+dp[2]=5
  dp[5]=dp[4]+dp[3]=8
So 5 steps can be climbed in 8 ways. Plain recursion would recompute dp[3] many times, the table computes it once.

PATTERNS YOU WILL MEET
- 1D: Climbing Stairs, House Robber, Coin Change, Longest Increasing Subsequence
- 2D grid: Unique Paths, Minimum Path Sum
- Two strings: Longest Common Subsequence, Edit Distance
- Knapsack: 0/1 Knapsack, Partition Equal Subset Sum (take or skip each item)
- Interval and partition: Word Break, Palindromic Substrings

COMPLEXITY
Time is the number of states times the work per state. Climbing stairs is O(n). Two-string DP is O(n x m). Space is the table size, often reducible by keeping only the last row or last two values.

COMMON MISTAKES
- Not defining the state clearly before writing code
- Wrong base case, or off-by-one in the table size (n + 1)
- Filling the table in the wrong order, so a cell is read before it is computed
- Using a huge value like Integer.MAX_VALUE and then adding 1 to it (overflow)

INTERVIEW TIPS
- Start with the recursive idea, then say "this repeats work, so I will memoize it"
- Always say what dp[i] means before you write any code
- Mention space optimisation after the working solution

PRACTICE ROADMAP
1. Easy: Climbing Stairs, Min Cost Climbing Stairs
2. Medium: House Robber, Coin Change, Longest Increasing Subsequence, Unique Paths, Word Break
3. Hard: Longest Common Subsequence, Edit Distance, Partition Equal Subset Sum

QUICK RECAP
- Never solve the same small problem twice, save the answer
- State, recurrence, base case, order
- Top-down is memoization, bottom-up is tabulation
