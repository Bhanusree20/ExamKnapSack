WHAT IT IS
A greedy algorithm builds the answer step by step, always taking the choice that looks best right now, and never goes back. It works when the best local choice also leads to the best overall answer. Interval problems are the most common greedy questions: sort first, then sweep once.

REAL-LIFE ANALOGY
Packing a bag for the most value: pick the best items first. Or giving change: always hand over the largest note that fits. For meetings in one room: choose the meeting that ends earliest, so the most meetings fit afterwards.

KEY TERMS
- Greedy choice: the best-looking option at the current step
- Sort first: most greedy solutions begin by sorting by start, end or ratio
- Interval: a pair [start, end]
- Overlap: two intervals share some time, start of the next is not after the end of the previous
- Merge: join overlapping intervals into one bigger interval

WHEN TO USE IT
- "Maximum number of non-overlapping meetings or activities"
- Merge, insert or remove intervals
- "Minimum number of arrows, platforms or rooms"
- Jump game and gas station style questions
- You can argue "taking the best now never hurts later"

CODE: MERGE INTERVALS
Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
List<int[]> merged = new ArrayList<>();
int[] current = intervals[0];
for (int i = 1; i < intervals.length; i++) {
    if (intervals[i][0] <= current[1]) {
        current[1] = Math.max(current[1], intervals[i][1]);
    } else {
        merged.add(current);
        current = intervals[i];
    }
}
merged.add(current);
return merged.toArray(new int[merged.size()][]);

CODE: JUMP GAME (CAN YOU REACH THE END?)
int farthest = 0;
for (int i = 0; i < nums.length; i++) {
    if (i > farthest) {
        return false;
    }
    farthest = Math.max(farthest, i + nums[i]);
}
return true;

WORKED EXAMPLE
Merge [[1,3], [2,6], [8,10], [15,18]]. They are already sorted by start.
  current=[1,3]   next=[2,6]    2 <= 3 overlap, merge into [1,6]
  current=[1,6]   next=[8,10]   8 > 6 gap, save [1,6], current=[8,10]
  current=[8,10]  next=[15,18]  15 > 10 gap, save [8,10], current=[15,18]
  end             save [15,18]
Result: [[1,6], [8,10], [15,18]]. One sort plus one pass.

PATTERNS YOU WILL MEET
- Sort by start and merge: Merge Intervals, Insert Interval
- Sort by end and keep: Non-overlapping Intervals, Minimum Number of Arrows
- Counting overlaps: Meeting Rooms II (sort or use a min-heap of end times)
- Reachability: Jump Game, Jump Game II
- Circular choice: Gas Station
- Scheduling: Task Scheduler, Partition Labels

COMPLEXITY
Sorting costs O(n log n), the sweep after it is O(n). So most interval problems are O(n log n) time and O(n) space for the output.

COMMON MISTAKES
- Forgetting to sort, or sorting by the wrong end
- Merging with < instead of <= (intervals that touch should usually merge)
- Not taking the maximum of the two end times when merging
- Assuming greedy always works, some problems (like coin change with odd coins) need DP

INTERVIEW TIPS
- Say why the greedy choice is safe: "choosing the earliest end leaves the most room"
- Test with a tiny counter-example, if greedy fails there, think DP
- State the sort key out loud, it is half the solution

PRACTICE ROADMAP
1. Easy: Meeting Rooms, Best Time to Buy and Sell Stock
2. Medium: Merge Intervals, Insert Interval, Non-overlapping Intervals, Jump Game, Gas Station
3. Hard: Meeting Rooms II, Minimum Number of Arrows to Burst Balloons, Task Scheduler

QUICK RECAP
- Sort first, then take the best choice that fits
- Intervals: sort by start to merge, sort by end to pick the most
- If greedy cannot be justified, use dynamic programming
